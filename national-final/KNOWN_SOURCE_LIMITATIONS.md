# 当前实现的已知限制

以下项目记录当前公开业务逻辑的已知边界。除变更记录中明确列出的超大 PAT、固定芯片协议矩阵、七款器件 SDI VOL 单线写入、固定 FUNC WIP 轮询、`1.0.5` 的 SRAM/I²C EEPROM 功能、`1.0.8` 的 SPI EEPROM 增量，以及 `1.0.9` 的固定串行存储器性能修复外，Electron 版不擅自扩展器件能力或更改协议语义。

## 明确未实现的页面选项

- SPI Flash 的 GALPAT 仍未生成；23LC1024 SRAM 的 GALPAT 已在 `1.0.5` 接入并限制最多 256 Byte；
- 自定义 SPI EEPROM 的 GALPAT 仍不生成；固定 25LC256 的 GALPAT 最多允许 256 Byte；
- 自定义 SPI Flash 只支持 MEMORY，不支持 FUNC；
- 设置图标没有对应设置面板逻辑。

## 已确认的源算法边界

- GD25LQ40E 的 FUNC SQI 在界面可选，但源门禁逻辑会拒绝生成；
- 旧自定义 SPI Flash 模式首次初始化可能把默认 TX1 从 Write Enable 覆盖为 Page Program；
- 旧自定义 SPI Flash 的 Checkerboard 配合奇数 Page 大小时可能生成小数 `LOOP`；
- 旧自定义 SPI Flash 地址使用 JavaScript Number，超过 53 bit 会失去整数精度；SDI/SQI 地址宽度不能整除 2/4 时可能丢低位；
- 旧自定义 SPI Flash 多页范围的默认 TX 数量不保证覆盖每个待写页，而现有自校验不会发现该缺口；
- 部分 PAT HEAD 的最后一个 Pin 标点以及 `CS` / `CS_N` 命名不统一；
- FUNC 校验和编辑后的重新校验覆盖较浅，校验文本出现失败项时仍可能允许导出；

`1.0.5` 新增的自定义 SRAM/EEPROM 不沿用上述静默地址截断：SRAM 地址限制为最多 24 bit，SDI 必须是 2 的整数倍、SQI 必须是 4 的整数倍；EEPROM 字地址只接受 8/16/24 bit。无效配置会在生成前显示中文错误，不会输出缺位地址 PAT。上述限制不改变旧自定义 SPI Flash 的既有行为。

## 已修复：超大 PAT 卡顿

- 原页面会同步逐 Byte 展开，并把每一行变成独立 `<div>`；约 50 万行会产生约 50 万个 DOM 元素并触发严重布局阻塞；
- `1.0.1` 将生成和校验改为可取消的协作式分批任务；
- `1.0.2` 取消固定 2,000,000 行拒绝限制，超过该内存阈值时自动改用磁盘临时文件流式生成、分段读取和流式导出；实际行数超过预估时也会在运行中自动迁移；
- 超过 12,000 行时改用 5,000 行分段安全预览，完整 PAT 仍完整导出；
- 50 万行专项测试实际生成 521,237 行，预览逐行元素数量为 0；
- 跨旧上限专项测试实际完成 2,084,312 行磁盘流式 PAT，并验证首末预览、整列替换和取消回滚；
- `1.0.9` 为固定 23LC1024、24LC02B、25LC256 使用独立 100,000 行流式切换点；全容量/最大模式分别验证 5,636,515、172,069、1,497,257 行，不再在 renderer 中积累或合并完整大文本；
- 23LC1024 不可压缩写模板按 64 Byte 分片让出 UI；553,740 行奇数长度 Checkerboard 回归确认写阶段持续 heartbeat，PAT 内容、LOOP、行数与完整SHA稳定；
- 全局行数采用 JavaScript 最大安全整数作为计数上限；固定器件仍遵守型号容量，实际最高规模取决于合法地址、磁盘空间和可接受的生成时间。

大文件安全预览是只读的；如需逐行手工修改全部内容，应先保存 PAT 后使用适合超大文本的编辑器。页面内“整列替换”仍会处理完整 PAT 的全部行。

## 已修复：七款器件 SDI VOL 写入总线

- `1.0.3` 已将 W25Q40CLSNIG、GD25Q40CTIG、BY25Q16ESOIG 的 SDI VOL `02h` 命令、24-bit 地址和 `00h` 数据固定为 SI/IO0 单线发送，数据区为 8 个 SPI 时钟且 SO/IO1 保持 `X`；
- `1.0.5` 按公开协议契约把同一单线写规则加入 GD25LQ40E 和 MX25U4033E/MX25U4033EM；
- `1.0.7` 依据器件协议与内部兼容性复核把 BY25Q80ES、W25Q64JVSSIQ 加入同一单线写规则；二者仍发送合法 `02h`，不改成 A2h；
- 除 MX 外的六款随后以 `3Bh` 读取：命令/地址单线、8 Dummy、4 个 IO1/IO0 双线数据时钟；MX 随后以 `BBh` 读取：命令单线、地址双线、4 Dummy、4 个双线数据时钟；
- 最终 `end: 0L1L11;` 保持两路 Low 供 VOL 测量；自动回归逐事务解码七款器件的真实向量，修正不进入 VOH、ICC、MEMORY 或其他型号。

## 已修复：固定芯片 Dual/MX Quad 协议矩阵

- `1.0.4` 依据公开芯片手册与内部兼容性复核，将固定型号按真实指令能力分为 A 类 `A2h+3Bh`、B 类 `02h+3Bh`、MX 类 `02h+BBh`，同时修正 MEMORY/FUNC 的数据阶段总线宽度；内部参考资料不进入公开仓库或测试输入；
- MX25U4033E/MX25U4033EM 的 Quad/SQI 已按非易失性 QE bit6、`38h` 4PP、`EBh` 4READ 生成，SPI/SDI 先恢复 QE=0，SQI 设置并确认 QE=1 后保持该状态；
- W25Q64JVSSIQ 已新增固定 SPI/SDI profile，可生成 MEMORY/FUNC；缺少足够公开验证依据，因此仍不启用它的 SQI FUNC；
- 页面固定型号状态计数已同步为 10 款；自动回归逐型号解码实际命令、地址、Dummy、数据总线宽度和 QE 状态序列；
- `1.0.4` 当轮未改 VOH、VOL、ICC；`1.0.5` 只按白名单修正 GD/MX 的 SDI VOL；`1.0.7` 再加入 BY25Q80ES/W25Q64JVSSIQ，但不扩大三款 A2h 芯片、SQI 或其他 DC 行为。

## 已修复：固定 FUNC 擦除/编程后的 WIP 轮询

- 旧 FUNC 写读在 Sector Erase 和 Page Program 后把 05h 状态读取误设为一次性展开，导致没有 `LOOP MATCH` / `LOOP END`；
- `1.0.7` 恢复真正的 WIP=0 轮询：05h 命令后进入 `LOOP MATCH`，S7～S1 不比较，S0 比较 Low，并在 S0 周期后 `LOOP END`；
- 每次 SR1 轮询按 8 bit × 4 vectors 完整输出，次数沿用各型号 profile；FUNC 写入和读回数据仍逐 Byte 展开，数据事务不使用普通 LOOP；
- 七款 02h 器件保持 SPI 单线写/SDI 回读，三款 A2h 器件保持双线数据写/SDI 回读；MEMORY、QE、VOH、VOL、ICC 与自定义器件路径未复用该 FUNC 专用 full-cycle 分支。

## 已补充：SRAM / EEPROM

- `1.0.5` 接入固定/自定义 SRAM、固定/自定义 EEPROM、TX 快速定位与相应结构说明；
- 23LC1024 覆盖 SPI/SDI/SQI、模式 1/模式 2 和受限 GALPAT；自定义 SRAM 覆盖 WRITE/READ/EDIO/EQIO/RSTIO/WRMR/RDMR；
- 24LC02B 与自定义 EEPROM 覆盖页写、当前地址读、随机读、顺序读、ACK/NACK、页边界和写等待；
- 新路径接入当前异步检查点、取消、流式临时文件与 5,000 行分段预览，不使用同步大 DOM 生成方式；
- 公开代表配置由团队独立构造，默认小样本和 50 万行回归输出以协议断言、字符数、行数和 SHA-256 锁定。

## 已补充：SPI EEPROM

- `1.0.8` 在既有公开行为之上接入 EEPROM 的 IIC/SPI 二级筛选、固定 25LC256、自定义 SPI EEPROM TX 与结构说明；
- 固定 25LC256 使用 32 KB 容量、64 Byte 物理页和 16-bit 线上地址；A15 为 DC，本工具规范化驱动 0。事务为 `06h WREN → 02h WRITE → 05h LOOP MATCH 2000 → 03h READ`，READ 无 Dummy，且不发送 NOR Flash 的 `20h`；
- 当前 SPI EEPROM 实现以公开源码中的协议契约为准：WRITE 后使用 `05h RDSR` 与 WIP 轮询，不以固定等待替代状态检查；
- 固定与自定义 WRITE 都按物理页拆分；非对齐首尾页只发送用户范围内的实际 Byte。自定义单组 WREN/WRITE/RDSR 会逐页重复；配置多组 WRITE 时，组数必须恰好覆盖物理页，否则生成前中文报错；
- 自定义地址宽度最多 24 bit，并使用 JavaScript 安全整数检查；清空 Page/地址宽度会先规范化为 64 Byte/16 bit，再用于计划、地址向量和说明，不能出现“头部16 bit、正文24 bit”或跨页 WRITE；
- 新路径复用显式生成按钮、协作式检查点、取消和 5,000 行窗口预览；`1.0.9` 后固定 25LC256 使用 100,000 行专用流式切换点，其他既有路径保持各自阈值；不引入自动刷新、逐行 DOM、远程 CDN 或一次性 FUNC 状态读取行为。

## 已修复：配置变化自动刷新 PAT

- `1.0.6` 移除地址、EEPROM、FUNC 与自定义擦除类型变化触发的后台自动生成；
- PAT 预览仅由“生成 Memory PAT”或“生成 FUNC PAT”显式更新，配置摘要仍实时更新；
- MEMORY/FUNC 与器件切换保留上一份已完成结果，超大 PAT 的流式临时文件不会因查看另一配置而被提前删除；
- 普通 PAT 手工编辑、整列替换、显式重置和导出功能保持；异步分段预览加入迟到回写保护。

这些边界不影响本次 Electron 外壳、离线化和原生保存验收，但可能影响特定 PAT 的 ATE 可执行性。连接设备前，应只选择已有公开协议依据和回归覆盖的器件/总线/模式，并让具备授权资料的设备工程师复核 HEAD、Pin Map、状态轮询、页覆盖与 LOOP 语法。

## 交付环境限制

- 当前机器已在不含 Node/Electron 的 PATH 下启动便携 EXE，但没有第二台干净 Windows 电脑可做物理跨机复验；
- EXE 未使用商业代码签名证书，SmartScreen 可能提示未知发布者；
- 应用是 PAT 文件生成器，不直接控制 ATE、DPS 或 PPMU，也不替代真实器件测试。
