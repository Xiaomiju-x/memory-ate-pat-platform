# 常见问题 / FAQ

## 这个项目到底是什么？

它是存储芯片 ATE/PAT 生成与分析项目，源于全国大学生集成电路创新创业大赛“胜达克”企业命题。仓库同时包含：

- 初赛 AT24C02 完整测试平台；
- 复赛 BY25Q40AL 竞赛优化平台；
- 已开源的全国总决赛多器件 PAT 软件平台 v1.0.9。

## 项目获得了哪些竞赛奖项？

参赛团队获得西南赛区一等奖，并获得全国总决赛一等奖（全国一等奖）。“一等奖”是奖项等级，不是赛区或全国名次口径。详情、区域证书和决赛纪念照片见[竞赛历程](competition.md)。

## 这是主办方、胜达克或 AdaptStar-E 的官方项目吗？

不是。这是参赛团队维护的开源项目。比赛、企业、芯片和设备名称仅用于说明项目背景及兼容目标。

## 初赛、复赛和决赛平台有什么区别？

根平台面向 AT24C02 起步，并扩展了多器件、多协议、工程导出与分析能力；复赛平台只解决 BY25Q40AL 的竞赛 PAT 约束，优先保证参数化生成、事务验证和现场工作流；决赛平台是独立 Electron 应用，覆盖多种 Flash、SRAM 和 EEPROM，并强化超大 PAT 的流式生成与离线桌面交付。三者都能生成 `.pat`，但不能混用引脚顺序、状态语义和时钟假设。

## 为什么主程序是一个很大的 Python 文件？

这是竞赛快速迭代和 Windows 单文件交付形成的架构：现场复制、打包和定位入口较直接，但模块审查和单元测试成本较高。现阶段保留行为稳定，后续在回归保护下拆分，见[架构说明](architecture.md)和[路线图](roadmap.md)。

## 需要哪些依赖？

主平台需要 Python 3.10+、`tkinter` 和 `customtkinter`；复赛 BY25Q40AL 入口运行时只使用 Python 标准库和 `tkinter`。决赛源码开发与构建使用 Node.js 22.12.0 和锁定的 npm 依赖，已发布的 Windows x64 便携版运行时不需要 Node.js。以仓库的 `requirements.txt`、`national-final/package-lock.json` 和[快速开始](quickstart.md)为准。

## 能在 Linux 或 macOS 上运行吗？

核心 Python 逻辑和 CLI 有跨平台基础，但主要 GUI、字体、DPI、文件对话框和 EXE 打包在 Windows 10/11 上开发。其他平台可以尝试 CLI，并欢迎提交可复现的兼容修正；仓库不会在未验证前承诺完整 GUI 体验。

## 为什么文档有时说 9 类，有时提到 IDDQ 或更多测试段？

“测试类型”在不同入口有三种计数口径：主算法族、GUI 可选项和实际导出的段。当前 CLI `--tests all` 映射 9 个主标识；`generate_samples.py` 也生成 9 类主测试，并将功能测试拆为多个 PAT；主平台另有 IDDQ 生成逻辑，DC 内也包含 IDDQ 相关测量点。评审覆盖率时应列出实际段名和配置，不用一个总数替代清单。

## 示例脚本是否等价于 GUI 的全部功能？

不等价。`generate_samples.py` 是稳定、易运行的 AT24C02 示例生成入口；GUI 还包含更多配置、格式、分析、模拟和单独导出动作。

## PAT 可以直接在 AdaptStar-E 上运行吗？

不能仅凭生成成功就作此保证。根平台实现 EStar 风格输出，但设备私有语法可能随软件版本、工程配置和授权格式文档不同。复赛公开版有格式与事务回归，也仍需目标机台导入、通道映射、电平时序和安全序列确认。

## 项目会连接或控制真实 ATE 吗？

默认不会。它主要生成文件、执行软件检查和分析。真实设备导入与执行发生在项目外部，必须由具备设备权限和安全流程的人完成。

## `H/L/X/Z` 分别是什么？

`H/L` 是比较期望，`0/1` 是驱动，`X` 是不比较或当前方言中的释放相位，`Z` 是高阻。具体电气行为取决于 ATE；复赛 BY25Q40AL 正式 PAT 明确只允许 `0/1/H/L/X`。详见[格式说明](formats.md)。

## 为什么 I2C 每 bit 用四个向量？

为了分别表达 setup、SCL 高电平采样、hold 和返回低电平四个相位，并与当前 EStar 风格格式保持一致。`TIM` 中的 `PERIOD` 是单条向量周期；因此 `tHIGH=tLOW=2×PERIOD`，`fSCL=1/(4×PERIOD)`。例如 `PERIOD=2500ns` 对应的 I2C 时钟是 `100kHz`，不是 `400kHz`。

## ACK Polling 为什么会拆成独立 PAT？

主平台导出器可以把写周期后的 ACK Polling 独立成段，便于 PRG 调度、超时处理和设备侧循环控制；TXT 预览仍可保留完整原始事务，供人工理解。

## 为什么公开仓库没有赛方黄金 PAT 和 FUNC 模板？

因为它们是赛事或企业提供的第三方资料，不属于团队可自由许可的作品。[第十届大赛章程](https://univ.ciciec.com/col.jsp?id=123)要求区分团队独立作品与企业资料，并限制未经授权传播赛事资源。公开版只包含团队代码、泛化测试和自生成样例，详见[知识产权与公开边界](legal-and-ip.md)。

## 复赛固定范围与自定义范围有什么区别？

公开版两者都由团队参数化引擎生成，并执行 PAT 语法和事务校验；固定范围只是方便复现的默认输入，不会读取赛方参考文件。合法持有相关资料者只能在授权范围自行离线核验；本项目不接收、不定位、不自动读取或提供相关资产/哈希/复制/对比工具，私有核验也不属于公开复现步骤。

## Shmoo、良率、Wafer Map 和 Datalog 是真实测量吗？

默认不是。它们可以使用软件生成或用户导入的数据；没有外部实测数据时，结果属于模拟或演示。报告和答辩中必须清楚标注，不能把模拟良率或参数分布描述为真实器件性能。

## 参数都来自哪一版 AT24C02 数据手册？

源码包含面向项目目标的参数预设，但 `AT24C02` 在不同厂商、后缀、温度等级和修订版下可能不同。生产或硬件执行前，应使用目标采购料号的正式数据手册逐项核对，并在贡献新 profile 时记录来源和版本。

## 能用于其他 EEPROM 或 Flash 吗？

根平台已有多种 I2C、SPI 和 Microwire 预设，但“列表里有型号”不等于完成该型号的真机资格认证。使用新器件时至少验证容量、地址字节、页大小、命令、状态寄存器、写周期、时序、电平和故障模型。

## 如何验证生成结果？

至少运行自动测试、格式验证、协议/事务检查和跨文件引用检查，再做目标 ATE 离线导入。真实 DUT 前先审查限流、供电、Pin Map 和安全序列。分层说明见[架构说明](architecture.md#验证层级)。

## 为什么仓库不应该保留所有历史 EXE、ZIP 和构建目录？

它们体积大、难以审查、容易混淆版本，也可能携带本机路径或旧资产。源码仓库保留可重建材料；正式二进制更适合放在 GitHub Releases，并提供版本、构建环境和 SHA-256。

## 证书图片或日志里有个人信息怎么办？

不要在公开 Issue 复制敏感信息。按 [SECURITY.md](../SECURITY.md) 的私下渠道报告，维护者会评估脱敏、替换图片或清理 Git 历史。

## 如何贡献一个新器件？

先提供公开数据手册来源、容量/页大小/地址/命令/时序字段，以及最小读写事务和预期向量。新增 profile 之后补协议测试、边界测试和至少一个由团队代码自生成的语义快照。流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 如何提一个高质量 Bug？

请附上：

- commit 或 release；
- Python 与 Windows 版本；
- 器件、协议、配置 JSON 或完整 CLI；
- 最小地址范围和测试段；
- 实际输出、期望输出；
- 验证器 / ATE 的原始错误文本；
- 已脱敏的最小 PAT 片段。

不要上传 API Key、账号凭据、未授权厂商文档、队伍内部资料或含个人隐私的截图。
