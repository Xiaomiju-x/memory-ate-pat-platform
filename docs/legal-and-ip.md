# 知识产权与公开边界 / Legal & IP Boundary

本页说明仓库为什么只公开团队独立创作部分，以及第三方赛事资料为何不属于公开复现输入。它是项目治理说明，不替代针对具体事实的法律意见；如规则或权利方要求发生变化，以官方最新文件和书面授权为准。

## 官方依据

- [第十届全国大学生集成电路创新创业大赛章程](https://univ.ciciec.com/col.jsp?id=123)：章程“其他事项”区分了团队独立创作作品与企业在赛题中提供的已有方案、参考案例、数据库、素材及其他背景资料；同时要求参赛过程中取得的赛事资源、企业软硬件工具和相关技术内容未经授权不得另作他用或传播。
- [第十届集创赛“胜达克”企业命题页](https://univ.ciciec.com/nd.jsp?id=1024)：用于核对本项目对应的官方企业命题和赛事背景。

据此，获得比赛资料访问权不等于获得公开再分发权；团队能开源的是自己拥有权利且允许发布的表达与实现。

## 本仓库可以包含

- 团队独立编写的 Python 源码、算法和 UI；
- 基于公开器件知识独立实现的协议原语、数据模式与验证逻辑；
- 团队编写的单元测试、边界测试、模糊/属性测试和 CI；
- 由公开版本生成器从公开配置生成、并经合规审查的样例输出；
- 团队撰写的架构、格式、复现、竞赛经历和安全说明；
- 已取得相关人员同意、并遮蔽二维码和证书编号的奖项展示图；
- 明确允许再分发且满足其许可证条件的第三方依赖或引用。

仓库根许可证只覆盖权利人有权许可的内容。商标、比赛名称、芯片型号和第三方材料仍归各自权利人所有。

## 本仓库不得包含

- 赛方原始黄金 PAT、黄金输出包或逐字节副本；
- 企业提供的 FUNC 参考模板、案例、数据库、素材、私有格式规范和培训资料；
- 赛事群、邮件、网盘、现场 U 盘或企业工具中取得且未获公开许可的内容；
- 对受限资产只做改名、换行、删注释、压缩、编码或轻微改写后的衍生副本；
- 能用于还原受限资产的长片段、补丁、完整哈希映射、下载地址或规避授权步骤；
- API Key、令牌、账号、私钥、本机凭据、未脱敏日志和他人个人信息；
- 无法证明来源和再分发权的芯片手册、ATE 手册、PPT、图片、EXE 或 ZIP。

“网上能找到”与“比赛时拿到”都不自动构成再分发许可。

## 公开版与比赛内部版

复赛现场内部版本曾在获授权环境中运行 30 项回归。这一事实可以说明团队当时的验证流程，但不能把私有输入随开源仓库发布。

公开版采用不同的可审计基线：

- 参数化生成器由团队源码产生输出；
- 测试输入由团队独立构造；
- 小型样例由公开代码自生成；
- CI 验证导入、地址边界、事务结构、状态字符和构建配置；
- 不把公开测试结果标注成“与赛方黄金文件逐字节一致”。

因此，内部 30 项回归与公开测试套件是两个不同口径。删除第三方语料是合规设计，不是测试缺失的掩饰。

## 私有核验不是项目功能

合法持有相关资料者只能在权利方授权范围内自行离线核验。本项目不接收、不定位、不自动读取或提供第三方赛事资产，也不提供其哈希清单、复制工具、对比工具或接入约定；私有核验不属于公开安装、测试、构建或复现步骤。

不要向维护者、Issue、Pull Request、Actions 日志或 Release 提交资产正文、原文件名、路径、哈希映射或其他可用于识别和还原资产的信息。本项目也不会帮助寻找非授权副本、绕过访问控制或从测试结果反推受限内容。公开生成器与测试必须在完全没有这些资料的环境中运行。

## 贡献者检查清单

提交 PR 前确认：

- [ ] 每个新增文件都是本人原创、项目既有文件的合规修改，或拥有明确再分发许可；
- [ ] 没有从赛方/企业 PAT 或文档复制长片段、注释、固定模板或独特排版；
- [ ] 测试 fixture 是自生成或最小化独立构造，不是私有语料的截取；
- [ ] 文件名、路径、日志和截图不泄露队伍、教师、账号、群聊或本机信息；
- [ ] 没有密钥、token、证书私钥、内部 URL 或云盘链接；
- [ ] 新增第三方依赖、图片或文档已记录来源和许可证；
- [ ] 生成物不包含私有输入，且 `git status` 只显示预期文件。

不确定时先不要提交文件。在 Issue 中描述“需要维护者私下进行来源审查”即可，不要先上传疑似受限内容。

## 发现误提交怎么办

如果发现秘密、个人信息或受限赛事资产进入仓库：

1. 不要在公开 Issue 粘贴内容或完整路径；
2. 立即按 [SECURITY.md](../SECURITY.md) 的私下报告方式联系维护者；
3. 说明受影响文件、首次出现的大致 commit、内容类型和是否已发布；
4. 维护者将评估下架、凭据轮换、Release 撤回和 Git 历史清理；
5. 历史清理后，所有协作者应按通知重新克隆，避免把敏感对象推回远端。

删除工作区文件并不等于从 Git 历史、Fork、缓存或 Release 中删除，因此需要按安全事件处理。
